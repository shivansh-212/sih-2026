BHU-ID Backend --- Skills

This file defines the technical skills and working capabilities required
to build and maintain the backend.

1. FastAPI

The developer/agent must be able to:

create FastAPI applications

organize routers

use dependencies

define request/response models

handle HTTP exceptions

use middleware

configure CORS

generate OpenAPI documentation

implement authentication dependencies

Preferred structure:

app/
├── main.py
├── api/
├── core/
├── models/
├── schemas/
├── services/
└── utils/

2. PostgreSQL

Must understand:

relational tables

primary keys

foreign keys

unique constraints

indexes

transactions

JSONB

basic query optimization

Avoid unnecessarily complicated SQL.

3. PostGIS

Must understand:

POINT

POLYGON

MULTIPOLYGON

geometry columns

spatial indexes

distance queries

intersection

containment

GeoJSON conversion

Useful operations include:

ST_DWithin

ST_Distance

ST_Intersects

ST_Contains

ST_Area

ST_AsGeoJSON

4. SQLAlchemy

Must understand:

SQLAlchemy 2.x models

relationships

sessions

transactions

eager/lazy loading

query construction

UUID fields

JSONB

PostGIS-compatible columns

Keep models readable.

5. Alembic

Must be able to:

initialize migrations

generate migrations

review generated migrations

apply migrations

rollback migrations

Never blindly trust autogenerated migrations.

6. Pydantic

Must use Pydantic for:

request validation

response serialization

configuration

nested API schemas

Do not expose SQLAlchemy models directly as public API contracts.

7. Authentication

Must understand:

password hashing

JWT

Bearer tokens

token expiration

authentication dependencies

authorization

role-based access control

The implementation should be simple enough for beginners to debug.

8. Security

Must understand:

password hashing

secret management

JWT validation

input validation

CORS

authorization

least privilege

safe error messages

Never expose:

password hashes

JWT secrets

internal stack traces in production responses

9. Dataset Processing

Must understand:

CSV

JSON

GeoJSON

Pandas

GeoPandas

Shapely

normalization

duplicate detection

missing values

The backend must preserve original source data while maintaining
normalized fields.

10. Spatial Matching

Must understand how to compare records using:

pincode

village

block

coordinates

geographic distance

polygon overlap

attributes

The developer must distinguish:

exact match

probable match

conflict

no match

11. AI/ML

For the MVP, understand:

feature engineering

weighted scoring

classification

confidence scores

false positives

false negatives

evaluation

Preferred progression:

Rule-based scoring
        ↓
Collect/inspect examples
        ↓
Simple ML model
        ↓
Evaluate
        ↓
Deploy only if useful

Do not jump directly to deep learning.

12. GeoJSON

Must be able to return:

{
  "type": "FeatureCollection",
  "features": []
}

Property features must contain frontend-relevant metadata.

13. Docker

Must be able to:

create Dockerfile

create docker-compose.yml

run PostgreSQL/PostGIS

configure environment variables

persist database data

inspect logs

restart services

14. Testing

Must understand:

pytest

API testing

authentication testing

database testing

permission testing

service-level testing

Focus on critical business logic first.

15. Debugging

When something fails:

Read the error.

Identify the failing layer.

Reproduce the problem.

Fix the smallest responsible component.

Run the relevant test.

Test the complete workflow.

Do not rewrite working modules because of a local bug.

16. Git

Use small meaningful commits such as:

feat: add jwt authentication
feat: add property model
feat: add map geojson endpoint
feat: add dataset normalization
feat: add matching service
fix: validate pincode
fix: protect admin routes

Avoid huge commits containing unrelated changes.

17. Frontend Integration

The backend developer must understand the frontend needs:

property search

property details

map GeoJSON

confidence score

source records

conflict status

authentication state

The API should serve the frontend rather than forcing frontend-specific
business logic into the database.

18. Required Working Style

Prioritize:

Correctness

Simplicity

Security

Maintainability

Demo reliability

Performance

Do not optimize prematurely.

Do not add technology merely because it sounds impressive.
